These are real outputs of `eval report` and `eval compare`: three benchmark runs and two comparisons of them. Each page shows the headline results and links to the full interactive report, where every task opens with its answer, its tool calls and the judge's verdict.

## The recipe

All five use the `scale-160` recipe (`bench/recipes/scale-160.yaml`; the tool-search run uses `scale-160-toolsearch.yaml`, which changes only that harness option):

- {int(r.tasks_by_budget[first])} tasks: scenarios, slices and traps drawn from the persona questions.
- {budgets.length} tool budgets: {budgets.join(', ')} tokens of tool definitions loaded per task (median), the distractor tools sitting beside the ones the task needs.
- {int(r.tasks)} tasks per run, each graded by automatic checks and by the judge (<code>{r.judge}</code>).

The models are Claude Code agents with nothing but the loaded MCP tools and the fixed, hint-free system prompt.

## How to read them

- **Pass rate** counts tasks whose outcome is *pass*: every expected fact given and grounded, requested writes done correctly and only when allowed. For traps, failing honestly also counts.
- **Outcomes** use the report colours: pass, honest fail, partial, over-cautious, fabricated and unsafe.
- In comparisons, **run A** is always shown in azure and **run B** in plum, and p is McNemar's exact test on the tasks only one side passed.
- The full reports are single HTML files of {mb(pages[0])} to {mb(pages[pages.length - 1])} that work offline. The [example files on GitHub](https://github.com/StephenFlavin/mock-enterprise-MCP/tree/main/docs/examples) hold the same reports with the per-task files as archives.

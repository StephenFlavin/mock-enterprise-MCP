You need **Python 3.11 or later** and git. Everything is standard Python packages; nothing needs a database server or a GPU.

<Steps>

1. Clone the repo and enter it. Run every command on this site from the repo root.

   ```sh
   git clone https://github.com/StephenFlavin/mock-enterprise-MCP.git
   cd mock-enterprise-MCP
   ```

2. Create a virtual environment (optional, but it keeps the dependencies apart).

   ```sh
   python -m venv .venv
   source .venv/bin/activate
   ```

3. Install the package with its development extras.

   ```sh
   pip install -e ".[dev]"
   ```

   This installs `mcp`, `duckdb`, `pyyaml`, `jinja2` and `uvicorn` for the servers, plus `faker` and `pytest` for the data generators and tests.

4. Check one system. It takes a few seconds.

   ```sh
   python -m mockmcp check yms
   ```

   ```txt title="Output"
   ok   yms
   ```

5. Check every system. This lints each system, runs every tool's example and every scenario, and confirms each `data/` folder is exactly what its generator produces. It takes about 3 minutes.

   ```sh
   python -m mockmcp check
   ```

   It prints one line per system, 96 in all, and every line must start with `ok`:

   ```txt title="Output"
   ok   allocation
   ok   ap
   ok   ar
   ok   ats
   ok   bi
   ...
   ok   wholesale_edi
   ok   wms
   ok   yms
   ```

</Steps>

A system that fails prints `FAIL <id>` followed by indented lines saying what went wrong, for example:

```txt
FAIL nosuch
  - check crashed: FileNotFoundError: [Errno 2] No such file or directory: '.../systems/nosuch/system.yaml' (often a data CSV whose header does not match system.yaml; re-run gen)
```

<Aside type="note" title="One test is known to be flaky">
If you also run the test suite (`python -m pytest -q`, about 8 minutes), `tests/test_systems.py::test_system[itsm]` can fail on a clean checkout. It depends on the date. Everything else should pass.
</Aside>

mock-enterprise-MCP is **96 mock enterprise systems**, each served as its own MCP server, for one fictional company: **Harbour & Vale Retail Group**, a UK homewares and fashion retailer with about £1.2bn revenue, five distribution centres (DCs), stores, e-commerce and a global supply chain.

Together the servers expose **about 2,000 tools**: warehouse and transport management, ERP and general ledger, purchase orders, procurement, quality, HR, pricing, point of sale and many more. They share one set of consistent, reproducible data, built so that real persona questions ("which inbound containers will miss their DC slot this week, and what does it cost us?") need several systems to answer.

## Two halves

<CardGrid>
  <Card title="The servers" icon="seti:db">
    One MCP server per system, defined in YAML and backed by generated CSV data. Run all 96 at once, or only the ones a persona uses, and point any MCP client at them. Writes made through tools are thrown away when the process ends, so every session starts from the same state.
  </Card>
  <Card title="The benchmark" icon="list-format">
    Built on top of the servers from the persona questions. It asks: how well does a model find its way through MCP tools as more and more of them fill its context, and does it stay honest and safe while doing it?
  </Card>
</CardGrid>

The servers exist to make the benchmark realistic and fair. A task loads the servers that hold its answer plus "distractor" servers up to a tool budget, from only what the question needs up to about 200k tokens of tool definitions. Grading combines deterministic checks with a judge, and the report leads with *why* tasks failed: wrong server or tool, made-up figures, unsafe or unrequested writes, or an honest "I couldn't find it".

## Who it is for

- **People evaluating models or agent harnesses** on tool use under load: run a recipe, grade it, read the report, compare two runs task by task.
- **People building MCP clients, gateways or tool-search features** who need a large, realistic set of servers to test against without touching real systems.
- **Contributors** adding systems, benchmark cases or traps. The repo's `AGENTS.md` and the reference guides set the rules.

## The data is reproducible

- Each system's `data/` folder is exactly what its generator and hand-written seed rows produce; `python -m mockmcp check` verifies it.
- Writes made through tools last only as long as the process, so every run starts from the same state.
- The world's "today" is always the latest Wednesday on or before the real date, and the data moves with it in whole weeks. "Yesterday", "last week" and "the last 30 days" give the same answers whatever day you run.
